# RT-5 真实能力实测 · 方法论

> 一句话：**五道标准化任务，每个真跑 3 次取中位数，机器判分，逐字原文全部公开。**

---

## 一、五道题

提示词原文是唯一事实来源，见 [`rt5-prompts.json`](./rt5-prompts.json)。
**自测与社区投稿必须用同一份原文**，否则两次运行不可比。

| 编号 | 任务 | 考察什么 |
|---|---|---|
| T1 | 写代码 | 能不能按规格写出可执行的函数（含非法输入处理） |
| T2 | 做调研 | 能不能给出带可访问 URL 的事实性清单 |
| T3 | 做表格 | 能不能严格按指定 CSV 表头与数据类型输出 |
| T4 | 做 PPT | 能不能按指定大纲结构输出（页数 + 每页要点数） |
| T5 | 订行程 | 能不能输出合规 JSON 并满足多重约束 |

题目设计的共同点：**都有一条可以被机器客观验证的硬约束**
（11 位手机号 / 完整 URL / 5 行 CSV / 8 页 / 预算 6000）。
能被机器判死，才不需要人拍脑袋。

---

## 二、怎么跑

1. **真实浏览器**（本机 Edge + 持久化 profile），不是调 API。
   调 API 测的是接口，不是用户实际拿到的东西。
2. **匿名会话**，账号档位记 `free`；登录后才测的记 `paid`。
   免费档的成绩不等于付费档。
3. **每题跑 3 次，取中位数** —— 不取最高、不取最新，
   否则一次偶然的好成绩就能左右一个产品的分数。
4. **等答案稳定**：连续两次「答案净长度」不变，且出现题面特征才收工。
5. **抽答案区，不抽整页**：只认答案容器（`.prose` / `.markdown-body` / `[data-testid=answer]` …），
   整页正文会被侧栏、页脚、提示词回显污染。

## 三、怎么判（判分器：`grader/realtest_grade.py`）

| 题 | 判分点 | 满分 |
|---|---|---|
| T1 | 12 个测试用例（含 `+86` 前缀、位数不足/超出、空串、非数字……）逐个执行 | 100 |
| T2 | 解析出 ≥3 个格式合法的 URL | 100 |
| T3 | 表头精确一致 / 恰好 5 行 / 人口是整数 / 房价是数字 / 可解析，各 20 分 | 100 |
| T4 | 恰好 8 页得 40 分（每差一页扣 5）；每页恰好 3 个要点累计 60 分 | 100 |
| T5 | 3 天 / 每天 ≥2 个 spot / 第三天 18:00 前 / 预算 ≤6000 / 可解析，各 20 分 | 100 |

**RT-5 总分 = 五项中位数的等权平均**，只算已测项，并在页面写明已测几项。

判分器纯离线，不联网。同一份 `raw_output` 永远得到同一个分数。

## 四、跑不出来怎么办

这是这份方法论最重要的一部分。

**跑不出来 ≠ 跑得差。** 以下情况一律标「未测」并写明原因，绝不给推测分、绝不记 0：

| 情况 | 标注 |
|---|---|
| 答案被锁在登录 / 注册之后 | 「答案被锁在登录之后（微信扫码 / 登录后继续）」 |
| 页面长时间停在「正在加载」 | 「投递后未产出可判分正文（等待 240s…）」 |
| 匿名试用次数用尽 | 「未登录且已超出试用次数」 |
| 网络不可达 | 「从我们所在网络环境无法建立连接」 |
| 反爬 / 人机验证 | 「被 Cloudflare 一类的人机验证挡住」 |

判定实现见 [`grader/_rt5_usable.py`](../grader/_rt5_usable.py)，
自测与社区投稿共用同一套标准。原则一句话：**宁可标未测，也不冤枉产品。**

反过来，有些 0 分是**我们自己的采集缺陷**造成的，这类必须修掉再重跑，
不能算到产品头上。真实发生过两次：

1. Perplexity 的引用来源角标被当成正文，插坏了 CSV 和 JSON；
2. 用「整页长度」判断答案出没出来，两个方向都会判错。

## 五、局限（写在前面，不藏在脚注里）

- **免费额度下的成绩 ≠ 付费版成绩**：额度、可用模型、并发上限都可能不同。
- **单次运行有随机性**：跑 3 次取中位数，同时公开 3 次原始分。
- **耗时不参与排名**：受网络、限流、排队影响太大，只记录不做分。
- **样本极小**：只能说明「这一轮、这一任务」的表现，不代表产品整体能力。
- **与 VI-100 不是一回事**：VI-100 测公开信息可核验程度，RT-5 测真跑任务的完成质量，两者不合并。
